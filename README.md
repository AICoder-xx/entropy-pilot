# Entropy Pilot

**Entropy 双边做市、真实库存网格与本地浏览器面板。**

简体中文 · [English](docs/i18n/README.en.md) · [繁體中文](docs/i18n/README.zh-TW.md) · [日本語](docs/i18n/README.ja.md) · [한국어](docs/i18n/README.ko.md)

Entropy Pilot 是在自己电脑运行的 Python 工具，支持 `io:SNDK`、`io:ANTH`，将钱包配置、风险预算、策略控制、成交图表和日志集中在本地面板。**当前面板界面为中文；以上链接是文档翻译，不是界面语言切换。**

> 面板的“启动实盘”会发送真实订单。公开命令行配置默认为模拟盘。做市、网格和邀请返佣都不构成收益保证。

> **库存网格为实验性功能，尚未经过实盘测试，目前仅完成代码层面的实现与测试；不代表实盘可用性已经验证。**

## 核心功能

| 功能 | 实际行为 |
|---|---|
| 双边做市 | 围绕盘口与参考价格提交 ALO/Maker 买卖报价，按库存偏移和风险限制调整 |
| 真实库存网格（实验性） | 支持做多与做空；开仓单建立库存，平仓单只减少已有库存；分别记录配对收益与账户盈亏。仅完成代码实现与测试，尚未实盘验证 |
| 多钱包、多市场 | 钱包与市场实例隔离，保留各自的订单、成交和恢复状态 |
| 本地面板 | GUI 填写钱包、编辑固定预算、选择策略、启动/安全停止、查看图表与日志 |
| 持久对账 | 保存订单意图；结果不确定时保留 `UNKNOWN`，先核对而非盲目重发 |
| 新手指南 | 页面提供 9 步高亮引导；只讲解，不代替用户保存配置或点击交易按钮 |
| 离线统计 | 按钱包、市场、策略和会话读取本地记录，区分实际费用与未到账奖励 |

## 快速开始：Windows

### 1. 准备环境

- 安装 [Git](https://git-scm.com/downloads) 和 [Python 3.11 或更高版本](https://www.python.org/downloads/)。安装 Python 时保留 Windows Python Launcher（`py`）。
- 本项目优先支持 Windows；本次安装、测试与浏览器流程使用 **Windows / Python 3.13** 验证。
- 模拟盘无需私钥。实盘需自行准备交易所资金账户，并在官方页面授权独立的 API 钱包；不要使用主钱包私钥。

也可在 PowerShell 中安装 Git 和 Python 3.13：

```powershell
winget install --id Git.Git -e --source winget
winget install --id Python.Python.3.13 -e --source winget
```

如果没有 `winget`，使用上面的 Git 与 Python 官方下载链接安装。安装完成后**关闭并重新打开 PowerShell**，再确认：

```powershell
git --version
py -3.13 --version
```

### 2. 克隆、安装、打开面板

```powershell
git clone https://github.com/AICoder-xx/entropy-pilot.git
cd entropy-pilot
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe dashboard.py
```

浏览器入口为 [http://127.0.0.1:8765/](http://127.0.0.1:8765/)。这些命令直接使用虚拟环境的 Python，**无需运行 `Activate.ps1`，也无需修改 PowerShell 执行策略**。

也可以下载并解压源码后，双击 `install.bat` 安装，再双击 `run_dashboard.bat` 打开。正常模式可以保存配置；`--read-only` 仅用于预览。

请通过 `run_dashboard.bat` 或 `dashboard.py` 启动后端，再访问上述网址。直接双击 `dashboard/index.html` 无法连接后端；这不是只读锁定，重新从正常入口启动即可。

全新安装默认为停止状态。**已有运行目录可能按持久状态自动恢复**，因此重开面板后先看实际状态。关闭浏览器标签不会停止后台服务或机器人。

## 新手使用：9 个步骤

1. **打开指南并查看状态。** 点击“新手指南”→“带我走一遍”，认识页面入口。教程可以跳过或退出，不会自动交易。确认当前不是只读模式，并检查是否有运行或恢复中的策略。
2. **准备独立 API 钱包。** 在交易所官方页面为资金账户授权 API 钱包。它仍有交易权限，密钥泄露可能造成损失。首次练习可先使用下面的模拟盘入口。
3. **填写本机钱包。** 在“钱包与配置”填写钱包名称、资金账户地址和 API 钱包私钥。资金账户填实际被交易的主账户或已获授权子账户，**不是 API 钱包地址**。
4. **保存并核对钱包。** 点击“保存本机配置”。同名钱包更新；已有地址或私钥留空时保留原值。更换资金账户请使用新钱包名称。保存不代表交易所授权已通过，启动时仍会核验角色和授权。
5. **设置风险预算。** 顶部选择 SNDK 或 ANTH，编辑做市单侧总额、最大仓位、最大挂单和会话回撤。点击“保存固定预算”会关闭该市场按权益自动放大，并作为下次启动参数；不保存就保留原配置。运行或恢复时须先安全停止。
6. **选择策略并确认启动范围。** 双边做市启动**全部启用钱包的全部已配置市场**，当前为 SNDK 与 ANTH；顶部预算市场选择不是做市启动范围开关。网格仅启动所选钱包与市场，另选方向、层数、间距、每单金额和锚点；有历史库存时不能随意变向。**库存网格为实验性功能，仅完成代码层面的实现与测试，尚未经过实盘测试；网格启动入口存在不代表实盘可用性已经验证。**
7. **先核对，再决定是否实盘。** 查看资金账户、实际持仓、现有挂单、可用保证金、预算与策略方向。只有决定承担风险后才点击明确标注的“启动实盘”。启动请求提交不代表账户检查和报价已成功。
8. **观察状态、成交和日志。** 区分“下次启动配置”与“当前/上次运行统计”。出现授权、预算或对账错误时先读具体提示；`UNKNOWN` 表示结果未确定，不能当作失败重新下单。
9. **安全停止并检查残余仓位。** 点击“全部安全撤单并停止”，等待状态确认，再在交易所核对仓位和挂单。**停止报价和撤单不等于平仓。** `flatten_on_halt` 只控制风控触发时的减仓行为；不要用关标签、强杀进程或删账本代替安全停止。

## 预算与配置

四项预算分别作用于**所选市场的每个启用钱包**，不是多个钱包共享一份总额。做市单侧总额是一侧报价梯子的总预算，不是每层金额；网格每单金额单独设置。最大仓位、最大挂单与会话回撤同时约束该市场网格。合计风险需要覆盖全部启用钱包和市场。

公开示例每市场、每钱包使用 `$12` 做市单侧预算、`$30` 最大净仓位、`$30` 最大挂单、`$3` 会话回撤。它们只是便于检查的小额起点，**不是推荐仓位或亏损保证**，也可能不符合当时市场的最小订单与数量精度要求。默认禁自动放大、禁购买 API 动作额度，未到账返佣投影为零。

| 文件 | 用途 |
|---|---|
| `config.json` | 默认命令行与做市模拟配置，模式为 `paper`；不包含私钥 |
| `config.grid.json` | 网格模拟配置，模式为 `paper` |
| `config.live.example.json` | 面板读取的实盘模板；凭证为空，需先在本机配置钱包 |
| `dashboard.config.json` | 本机面板预算，保存固定预算时写入 |
| `dashboard.config.example.json` | 没有本机预算文件时使用的小额默认值 |
| `wallet.local.json` | GUI 保存的本机凭证；格式参考 `wallet.example.json` |
| `.env` | 可选的单钱包 CLI 凭证文件，参考 `.env.example`；只有 `live.env_file` 显式指定时读取 |
| `state/`、`logs/` | 订单、成交、库存及运行记录；恢复需要保留 |

面板预算保存后无需重开页面，更新的是下次启动配置。手动修改其他配置时，先安全停止相关策略，再重启面板使其重新读取。两份预算文件都缺失或本机文件损坏会明确报错，不会回退到隐藏的大额预算。

命名钱包使用自己的 JSON 凭证，不混用全局 `.env`。单 `primary` 钱包仍支持“进程环境变量 → 显式 `.env` → 本机 JSON”的优先级；已有全局环境变量可能影响它，面板会提示。推荐使用清楚区分的命名钱包，例如 `wallet1`。

## 模拟盘、实盘与只读预览

```powershell
# 只检查行情
.\.venv\Scripts\python.exe main.py --config config.json --check

# 模拟盘：不发送真实订单
.\.venv\Scripts\python.exe main.py --config config.json
.\.venv\Scripts\python.exe main.py --config config.grid.json

# 只读面板：禁止保存、交易控制和自动恢复
.\.venv\Scripts\python.exe dashboard.py --port 8767 --read-only
```

Windows 也提供 `check_market.bat`、`run_market_maker.bat`、`run_grid.bat`。模拟盘用于熟悉运行方式，不能还原真实队列位置、完整滑点或盈利表现。**普通面板的策略启动按钮是实盘入口，不会因 CLI 配置为 paper 而变成模拟按钮。**

实盘执行的支持范围仍为 Windows。签名锁已提供 Windows 和 POSIX 实现，按实际 API 签名身份跨进程串行；Linux/macOS 的交易流程尚未完成实机验收，仅用于开发者自行验证 paper 或只读模式。Windows 的安装与功能测试也不等于实盘成交或长期收益认证。新旧版本采用不同的锁协议，升级前必须安全停止旧版本，不能混跑；同一 API 钱包也不要同时交给其他程序或电脑交易。

## 密钥、恢复与数据口径

- Windows 面板新保存的 `wallet.local.json` 使用**当前 Windows 用户的 DPAPI 加密**；页面不读回私钥。旧明文文件保持读取兼容，只有在面板再次保存时才原子升级，不会自动迁移，也不会生成明文备份。`.env` 仍是用户自行管理的明文输入；非 Windows 不会降级为明文保存。密文通常不能直接迁移到另一台电脑或另一用户。不要上传这些文件、`state/`、`logs/`、密钥截图或账户诊断文件。
- 保存钱包不会验证所有交易所权限；运行时仍会检查。不要把主钱包私钥交给程序作者或其他人。
- 更新前安全停止，保留原配置、凭证与状态，不导出明文秘密。不要用他人的台账初始化自己的账户，不要删状态来绕过 `UNKNOWN`、库存冲突或迟到成交。先核对交易所原订单和仓位，再处理具体恢复提示。旧摘要没有结构化恢复证据时不自动恢复；正常启动仍需通过停机对账。
- 如果签名进程在调用中异常终止，会保留 `SIGNING_INTERRUPTED` 保护。核对交易所原订单和系统时间后，可在官网创建新的专用 API 钱包，再在面板更新原钱包名称的 API 私钥；资金账户和旧账本保持原位，未确定订单仍须对账。不要删除签名锁记录来绕过保护。
- 自动付费购买 API 动作额度尚无完整支付恢复，因此 `auto_reserve_actions=true` 会明确拒绝；只读额度查询保留。
- 网格配对价差收益不等于账户净收益；已实现价格盈亏减手续费不包含全部资金费、浮盈亏、转账和未到账返佣。30 秒 markout 是成交后价格变化指标，不是最终损失。缺失数据不能当零。
