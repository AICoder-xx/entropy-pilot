# 工程质量与支持边界

## 运行平台

正式本地使用入口为 Windows / Python 3.11 或 3.13，双击 `run_dashboard.bat`。交易测试不等同于真实交易验收；真实库存网格继续作为未实盘验收的实验性功能。

Linux 的签名互斥提供 POSIX 实现，CI 对 Windows 和 Ubuntu 的两种 Python 版本运行离线测试。CI 文件已加入源码，只有远端成功运行记录才能证明远端平台通过；不能从配置存在推断跨平台验证完成。非 Windows 钱包写入不会降级为明文。

## 本地工程检查

开发者安装 `requirements-dev.txt` 后运行：

```text
python scripts/check_quality.py
```

该入口依次检查依赖、全部工作源码的 Ruff 规则、列明范围的 Mypy、所有面板 JavaScript 的语法、离线测试和分支覆盖。Node.js 只用于开发检查，普通面板运行无需 Node.js。测试使用临时文件、合成账户和模拟 SDK，不需要真实钱包、资金或网络下单。

当前类型检查范围以 `pyproject.toml` 的 `tool.mypy.files` 为准；这不是全工程严格类型检查。静态检查并不证明交易策略、SDK 或交易所的行为。覆盖率同时记录分支，整体门槛和关键恢复/持久化/签名模块门槛分开执行，避免被页面代码稀释。

覆盖率分母以 `tool.coverage.run.source` 的明确名单为准：交易核心、入口、面板及停机恢复模块。独立分析工具、安装/打包脚本和 JavaScript 不计入 Python 覆盖率；其静态检查、HTTP/浏览器行为和发行验收单独报告。不得将这个数字称为所有文件的覆盖率，也不得用代码行数代替覆盖率。

## 每次交付应分别报告

1. 实际源码和发布包测试：文件范围、版本、通过、失败、跳过及原因。
2. 交易状态不变量：先落盘再提交、未知结果不重发、跨策略重启保留门闩、所有权及预算边界。
3. 故障注入：磁盘刷盘/替换失败、进程突然退出、签名持锁进程中止、请求取消仍有工作线程存活。
4. 用户入口：面板实际打开，配置、预算、策略、指南和默认可见模块完整；保存与刷新/重启结果一致。
5. 已知缺口：未测平台、未运行的远端 CI、未完成的实盘和长期验证必须独立列出。

测试通过只说明已写断言的场景成立。文件过大、职责混杂、按文案恢复、密钥明文和无持续检查属于额外审查维度，不能因为测试通过而省略。修复完成后还要根据本轮变更做一次独立检查，报告具体发现而非笼统评分。

## 发布与凭证

运行包继续由 `build_public_release.py` 允许名单生成。加 `--include-dev` 可生成含测试、CI 和开发工具的源码包，两者均从安全示例生成默认配置，禁止把工作目录直接打包。既有本机钱包、账本、日志及历史包不进入发布。

Windows 在 GUI 下次保存钱包时使用当前用户 DPAPI 加密；旧明文保持读取兼容，不因升级自动迁移。加密文件依赖当前 Windows 用户/系统密钥，复制到另一台机器或另一用户不能当作已验证迁移；跨机器应由用户重新配置已授权的 API 钱包。DPAPI 防止文件被离线直接读出，不保护已被当前用户权限恶意程序控制的运行环境。

付费动作额度自动购买原为默认关闭，因尚无持久费用意图与支付 UNKNOWN 对账，本版本明确拒绝启用。只读额度查询保留。关闭此未验证路径并不等于已实现支付恢复。

配置和恢复字段的变化见各模块说明与[更新日志](../CHANGELOG.md)。中文提示仅展示，不能决定自动交易恢复；旧状态、未知错误码和未确定订单均不凭文案推断为安全。
