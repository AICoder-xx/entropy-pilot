# 恢复状态与停止语义

## 稳定恢复协议

`entropy_bot/recovery.py`定义FailureCode和版本化RecoveryState。自动恢复使用精确运行身份、错误类型、对账结果及明确布尔字段；不按中文错误文字、子串或展示函数返回值决策。

只有明确的网络故障且订单已对账才允许进入自动恢复核验。旧版本状态、未知代码、错run_id、授权/TLS/协议错误、订单UNKNOWN、签名中断及其他风险错误均默认拒绝。

运行摘要携带recovery字段。尚未产生摘要的子进程启动失败写入独立、绑定本次run_id的失败记录，避免与面板心跳争抢控制文件。普通退出不能抹去此前故障分类。

## 人工停止优先

停止操作在等待启动锁前持久化停止代次和禁止自动恢复标记。自动恢复在每次关键等待后重新核对，Start取得锁时检查最初恢复决策对应的运行和代次，不能把更新后的Stop状态当成新启动许可。

引擎在撤单、网络刷新和账户同步完成后再次消费停止信号，不继续进入报价协调。停止到达之前已经发出的请求仍需对账，不能声称撤回了已经发送的交易。

## 对账和手动恢复

手动Start可以对旧运行做有界只读查询及合格补录；未知身份、未决订单、未清挂单和外部活动仍阻止启动。旧摘要不是自动恢复授权。已知意图事件缺有效cloid时抛出稳定错误，不能静默跳过。

签名中断按[签名互斥说明](ENGINEERING_BROKER.md)处理，不能删除锁或账本绕过。中文提示只负责解释原因，变更语言不能改变动作许可。
